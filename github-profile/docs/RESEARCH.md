# Research notes and references — July 2026

## Method

The research used broad GitHub profile catalogues, topic/search result sets and targeted queries for QA Engineer, SDET, Software Quality Engineer, Test Automation Engineer, Staff QA and Quality Architect. It then inspected a smaller, verifiable sample of public QA profiles and the primary repositories/documents behind common widgets.

This is an aggregate trend review, **not a claim that hundreds of QA profiles were individually audited**. That distinction matters: a large search result set identifies patterns; it does not justify pretending every result received a detailed review.

## Patterns that consistently help

- Role and value proposition visible in the first viewport
- Three to five pinned repositories selected for relevance and diversity
- Project proof: problem, approach, test evidence, architecture and result
- Capability groups instead of long logo inventories
- English-first copy for international recruiting
- Direct contact and a concise experience narrative
- One restrained visual system with progressive disclosure

## Patterns deliberately not adopted

- Trophy walls, streaks and visitor counters
- Top Languages presented as proficiency
- Multiple external statistic services duplicating native GitHub activity
- Unsupported impact percentages
- Lottie, JavaScript, CSS cards or iframe concepts that GitHub README sanitization cannot render
- Heavy looping GIFs or several simultaneous animations
