# Test strategy

## Objective

State which release decision this suite supports and which risks would make that decision unsafe.

## Risk matrix

| Risk | Likelihood | Impact | Detection | Prevention/mitigation |
| --- | --- | --- | --- | --- |
| [Risk] | [Low/Medium/High] | [Low/Medium/High] | [Test or signal] | [Design or process] |

## Test levels and scope

Explain why each scenario belongs at unit, component, API, integration or E2E level. Record deliberate exclusions.

## Environments and data

Define environment assumptions, data ownership, isolation and cleanup.

## Release signals

List blocking gates, advisory signals, flake policy, severity model and rollback criteria.

## Reporting

Define what is kept, for how long, and how sensitive information is removed from artifacts.
